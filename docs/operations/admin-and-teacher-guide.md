# Project M Admin and Teacher Guide

## Teachers

Use only tags assigned to you. Pages can be drafted, published, exported as `.mpx`, imported, and restored from revision history. Attachments remain unavailable until the independent verification worker marks them ready.

Assignments and quizzes should be published only after audience and deadline review. Saving a mark does **not** release it: review the value and feedback, then use the separate release control. Regrading withdraws the previous release until the new grade is deliberately released. Never place safeguarding notes or unrelated personal data in learning content or feedback.

If access appears wrong, stop and report the account, tag, route, UTC time, and visible error—do not work around it by retagging content or sharing files externally.

## Institution admins

Use least privilege. Grant roles and tag memberships only from an approved source and include a meaningful reason. Prefer roster dry-run before apply; the sync preserves manual memberships, queues people who have not signed in, and disables sync-managed leavers without deleting history.

Guardian links are admin attestations, not self-service claims. Follow the school-approved evidence policy, verify the normalized email and pupil, record the reason, and revoke promptly when disputed or expired.

Migration imports accept bounded JSON manifests, create drafts, require existing tags, and never silently overwrite a changed prior import. Review every report before apply and manually sample resulting content.

Use the audit and operational reports for support, not as compliance exports. Escalate suspected exposure, compromised accounts, harmful content, or incorrect guardian linkage using the incident runbook.
